# 红旗 H5 安装步骤与排错

## 车机侧安装步骤

准备：USB 公对公数据线（部分机型需 OTG 转接线）、已装 platform-tools 的电脑。

1. **进工程模式**
   车辆设置 → 系统 → 系统信息 → 在「软件版本信息」上**连续点击 5 次**
   → 密码框输入：`hongqih5`

2. **打开调试**
   点「诊断模式 / USB 诊断」→ 打开「adb / USB DEVICE MODE」及 adb enable 开关。

3. **连接**
   数据线插车机（储物箱左侧带数据标志的 USB 口），另一端接电脑。
   部分车型需先把模式从 HOST 切到 DEVICE。

4. **安装**
   ```bash
   adb devices                    # 确认识别到车机
   adb install -r "目标.apk"
   ```
   备选：工程模式切 DEVICE → 电脑装 360 手机助手 → 连接后
   「已装应用 / 安装本地应用」→ 选择 APK。

5. **收尾**
   切回「USB HOST MODE」→ 关闭 ADB → **重启车机** → 检查桌面图标。

## 报错对照表

| 报错 | 根因 | 对策 |
|---|---|---|
| 应用未安装 / 解析包错误 | 包名不在白名单 | 换用实测放行的白名单包名 |
| 签名冲突 / 已存在 | 同名包被其他签名的应用占用 | 用 AOSP testkey 重签；或先卸载占用者 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 签名与已装同名应用不一致 | 同上 |
| 装上了但闪退 | 代码包名与 manifest 失配 / dex 被改坏 | 只改身份标识，勿 apktool b 重编译 |
| 装得上、能启动，桌面无图标 | 缺桌面注册 meta-data | 注入 4 项 meta-data + 重启车机 |

## minSdk 限制

部分应用的 `minSdkVersion` 较高（例如要求 Android 9+，即 API 28）。
若车机系统版本低于该值，改包名**无法解决**——需要另行降 minSdk，
且降了也可能在运行时缺少 API。交付前先用 `--detect` 或读清单确认。

## 交付前自查

- [ ] 目标包名没有被用户已有应用占用（否则会覆盖）
- [ ] 在交付说明里明确写出"哪些文件**不要**安装"
- [ ] 签名证书指纹与用户手上的可用样本一致
- [ ] 已提示用户"装完必须重启车机再看桌面"

## 预期管理与风险

- 面向其他品牌车机开发的应用在红旗上功能可能不完整，例如 HUD、仪表投屏
  等特性不会生效。这一点应如实告知用户，避免预期落差。
- 安装第三方应用可能影响质保。本方案只安装普通应用、**不触碰系统分区**，
  属可控范围。
- 仅供个人在自己的车辆上使用。

## 版本迭代时的注意事项

- **签名密钥必须始终复用同一把**，否则新版本无法覆盖升级旧版本，
  只能先卸载再装。
- 每次出新版本，若包名不变，应在交付说明中写明"覆盖了旧版同名文件"，
  并给出 SHA-256 供用户核对。
